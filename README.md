# 🎰 土制量化梭哈机器人

> 严肃学习 FX 久留美精神。几百刀，图一乐：赚了是策略牛逼，亏了是市场不懂我。

挂在 GitHub Actions 上的加密货币自动交易机器人：每小时醒一次，看 K 线、算信号、该梭就梭、该跑就跑，顺手爬点行情数据。默认**模拟盘**，玩明白了再上真钱。

- **交易所**：Gate 现货（底层是 [ccxt](https://github.com/ccxt/ccxt)，想换交易所改一行配置）
- **策略菜单**：趋势 / 动量 / 抄底 / 情绪 / 网格 / 轮动，外加两个对照组（无脑囤币、猴子扔骰子）。全部拿 Gate 真实 K 线、按真实费率回测过，成绩单见下文
- **风控**：止损、止盈、移动止损、熔断（亏到预算的一半自动罢工）
- **爬虫**：恐惧贪婪指数、CoinGecko 热搜、Gate 涨跌榜、股票代币相对正股的溢价（美股周末休市，代币还在 24/7 跑）
- **推送**：微信（Server酱 / PushPlus）、Telegram、Bark

## 它是怎么跑的

```
GitHub Actions（每小时第 7 分钟）
└─ python -m bot.run
   ├─ 拉最近的已收盘 K 线（Gate 公共接口，不需要 key）
   ├─ 策略 → 目标仓位 0~1（1 = 梭哈，0 = 空仓）
   ├─ 风控覆盖：止损 / 止盈 / 移动止损 / 熔断
   ├─ 目标仓位 vs 当前仓位 → 下市价单（模拟盘假装成交，实盘真下单）
   └─ 记账 → 推到 bot-data 分支（下次运行接着用）
```

几个设计上的讲究：

- **幂等的“目标仓位”写法**：策略不说“买/卖”，只说“我现在应该持有多少”。GitHub 的定时任务经常延迟、偶尔重跑或漏跑，这种写法跑几次都不会重复下单。
- **回测和实盘是同一套代码**：`decide → plan_order → 成交 → 记账`，回测只是把成交换成“下一根 K 线开盘价 + 手续费 + 滑点”。
- **每个机器人只认自己的账本**：预算多少、手里多少币、多少现金。实盘时下单金额同时受账本和交易所真实余额限制，账户里别的钱它不碰。
- **掉单自愈**：每笔实盘订单都带备注（Gate 的 `text` 字段），万一下了单但账本没存上（比如推送失败），下次运行会按备注把订单认领回来。
- **状态放 `bot-data` 分支**：机器人每小时提交一次，但只提交到 `bot-data`，`main` 只放代码和配置，你改配置永远不会和机器人冲突。

## 快速开始

### 1. 本地先玩（可选）

```bash
pip install -r requirements-dev.txt
```

```bash
python -m pytest
```

```bash
python -m bot.backtest --strategy sma_cross --symbol BTC/USDT --timeframe 4h --days 730
```

```bash
python -m bot.run --dry-run
```

`--dry-run` 只看信号不下单不存盘。不加就是真的跑一步模拟盘（状态写到 `state/paper/`）。

### 2. 在 GitHub 上开模拟盘

仓库 → **Settings → Secrets and variables → Actions → Variables**，新建：

| 变量 | 值 | 作用 |
|---|---|---|
| `BOT_ENABLED` | `true` | 机器人定时任务总开关 |
| `CRAWLER_ENABLED` | `true` | 爬虫定时任务总开关 |

然后在 **Actions** 页面能看到「梭哈机器人」每小时跑一次，每次运行的 Summary 里有一张表：每个机器人做了什么、净值多少。账本、成交记录、净值曲线在 `bot-data` 分支的 `state/` 目录，爬虫数据在 `data/` 目录。

想马上跑一次：Actions → 梭哈机器人 → Run workflow。

## 配置

全部在 [`config.toml`](config.toml)，改完 push 就生效。每个 `[[bots]]` 是一个独立机器人：

```toml
[[bots]]
name = "btc-trend"          # 名字（小写字母/数字/-/_），状态文件按它存
symbol = "BTC/USDT"         # 交易对，Gate 上有的现货都行，包括 NVDAX/USDT 这类股票代币
timeframe = "4h"            # K 线周期
strategy = "sma_cross"      # 策略名，见策略菜单
budget = 100                # 这个机器人能动用的钱（计价币）
size = 1.0                  # 梭哈系数：信号满格时用多少比例的资金，1 = 梭哈
params = { fast = 20, slow = 60 }   # 策略参数，不写就用默认值；写错名字会直接报错
risk = { stop_loss = 0.15, trailing_stop = 0.25, kill_switch = 0.5 }
```

风控参数（都写小数，0 = 不启用）：

| 参数 | 意思 |
|---|---|
| `stop_loss` | 跌破持仓成本这么多就割（0.15 = -15%） |
| `take_profit` | 赚这么多就落袋（0.5 = +50%） |
| `trailing_stop` | 从持仓以来的最高价回撤这么多就走 |
| `kill_switch` | 净值跌到预算的 `1 - kill_switch` 就清仓罢工（0.5 = 亏一半收手）；想复活就删掉 `bot-data` 分支里这个机器人的状态文件 |

止损 / 止盈 / 移动止损触发后会进入**冷静期**：策略信号先归零一次才允许重新上车，免得刚割完肉下一小时又原价追回去。

## 那些坑

- **手续费才是最大的对手**。Gate 现货吃单 0.2%，一买一卖 0.4%。1 小时级别来回折腾的策略，回测里基本都被手续费吃干了（看排行榜里猴子的下场）。想高频，先把费率降下来（GT 抵扣 / VIP），再在 `config.toml` 的 `fee` 里改成真实费率重新回测。
- **GitHub 的定时任务不准时**。cron 写的是每小时第 7 分钟，实际可能晚几分钟到几十分钟，高峰期偶尔直接跳过一次。机器人按“目标仓位”设计，晚了就晚了，不会乱下单；但别指望它做秒级止损。
- **Gate 的 K 线历史有限**：每个周期只能往回查约 10000 根 —— 1h 大概 14 个月，4h 大概 4.5 年，日线不受影响。策略需要的 K 线根数（warmup）最多 990 根。
- **仓库是公开的**：`bot-data` 分支里的账本、成交记录所有人都能看到（不含任何密钥）。介意的话把仓库改成私有；私有仓库每月有 2000 分钟免费 Actions 额度，每小时跑一次大约用 700~1500 分钟，爬虫每 3 小时一次再加 ~250 分钟，够用但别再加别的了。
- **公开仓库 60 天没动静，GitHub 会自动停掉定时任务**。机器人每小时往 `bot-data` 提交一次，算“有动静”；如果你关掉了 `BOT_ENABLED` 又很久不碰仓库，记得回来点一下。
- **同一个账户跑多个机器人**：别让两个机器人交易同一个币（账本会打架），预算加起来别超过账户里的钱。最省心的做法是给机器人单独开一个子账户。
- **复活 / 重置**：熔断后想复活、或者想清空某个机器人的战绩，删掉 `bot-data` 分支里 `state/<模式>/bots/<名字>.json` 就行（实盘请先确认它手里没有币，或者手动卖掉）。
- **模拟盘不是实盘**：模拟盘按实时价格 + 手续费 + 滑点假装成交，不会考虑盘口被你吃穿。几百刀在 BTC/ETH 上无所谓，在小币和股票代币上会偏乐观。

## 目录

```
bot/                机器人本体
  strategies/       策略，一个流派一个文件，新建文件 + @register 就能用
  engine.py         决策：策略信号 + 风控 → 目标仓位 → 订单
  wallet.py         虚拟账本
  brokers.py        模拟盘撮合 / Gate 实盘下单
  backtest.py       回测
  run.py            Actions 每次跑的入口
crawler/            爬虫
research/           研究台、排行榜、研究笔记
scripts/            Actions 用的小脚本（bot-data 分支读写）
.github/workflows/  定时任务：机器人、爬虫、测试、手动回测
```
